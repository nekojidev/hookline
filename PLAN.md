# Hookline — план на семестр (Pudge Wars, 8 лаб)

Курс: JavaScript — мультиплеєрна браузерна гра в реальному часі.
Проєкт: клон **Pudge Wars** — топ-даун арена, розділена річкою/деревами, гравці тягнуть один одного м'ясним гачком у небезпечну зону.

Джерело програми: [courses/javascript/README.md](https://github.com/rmalkevy/Programming-Practice-Projects/blob/main/courses/javascript/README.md)

---

## Ядро механіки (незмінне протягом усього семестру)

- **Арена**: прямокутне поле, посередині річка/смуга дерев ділить його на дві половини.
- **Персонаж** ("Pudge"): повільний рух (WASD/стрілки), обмежена швидкість, тертя.
- **М'ясний гачок**: skillshot-снаряд по прямій лінії, обмежена дальність.
  - Влучив у ворога → миттєво підтягує його до кастера; урон більший, якщо в процесі підтягування ворог проходить крізь дерева/річку.
  - Можна кинути в стіну/дерево, щоб підтягнути **себе** (мобільність).
  - Кулдаун, який зменшується з рівнем/золотом.
- **Золото**: за вбивства/асисти → проста крамниця (бутси швидкості, +дальність гачка, реген).
- **Перемога**: рахунок вбивств за часовим лімітом.

Це ядро навмисно просте — воно не змінюється по лабах, лаби додають *шар* (рендер → об'єкти → мережа → типи → тести → продакшн) навколо нього.

## Lab 1 — Event Loop Is the Game Loop

**Фокус**: call stack, task/microtask queue, `requestAnimationFrame`, ES modules, closures, canvas.

**Проєктний крок**:
- Скелет: Vite + vanilla JS, ES modules (`"type": "module"`), `.nvmrc`, вибрати ESLint(flat)+Prettier або Biome — і більше про це не думати.
- Canvas: арена з річкою/деревами (можна поки прямокутники-заглушки), один керований персонаж.
- **Fixed-timestep** симуляція (accumulator pattern), окремо від рендеру на `requestAnimationFrame`.
- Рух з інерцією: прискорення, тертя, максимальна швидкість, межі арени.
- Демонстрація "чому event loop важливий": штучний блокуючий синхронний виклик — показати, як він заморожує кадри.

**Deliverable**: персонаж плавно рухається на 60 fps з фіксованим кроком симуляції незалежно від навантаження рендеру. Тег `lab-01`.

## Lab 2 — Objects, Prototypes, and `this`

**Фокус**: `class` + один рівень `extends`, правила `this`, композиція, `Map`/`Set`.

**Проєктний крок**:
- Модель сутностей: базовий `Entity` (позиція, швидкість, радіус, `draw()`); `Player`, `Hook`, `Tree`, `GoldPickup` — через композицію компонентів, а не глибоку ієрархію.
- Гачок як сутність зі станом: `flying → attached → retracting`.
- Колізії: коло-коло (гачок↔гравець, гачок↔дерево), межі арени, зона річки як тригер.
- `EntityManager` на `Map` (ключ — id) для спавну/despawn і ітерації update/draw.
- Два локальні гравці (WASD проти стрілок) на одній клавіатурі — щоб перевірити гачок-і-підтягування без мережі.

**Deliverable**: два локальні персонажі можуть гачити одне одного, підтягування працює, протягування крізь дерево дає бонусний урон.

## Lab 3 — Asynchronous JavaScript

**Фокус**: Promises, `async/await`, мікротаск-черга, `fetch`, `AbortController`, `EventTarget`, Web Audio.

**Проєктний крок**:
- Asset pipeline: `Promise.all` для спрайтів (гравець, гачок, дерево, фон) і звуків (постріл гачка, влучання, промах, вбивство) — з екраном завантаження й прогрес-баром.
- Локальне лобі-меню (поки без мережі) на `EventTarget`-подіях замість фреймворку.
- Web Audio: звук пострілу гачка з `AbortController` для коректного скасування/перезапуску; фонове амбієнтне аудіо річки.

**Deliverable**: екран завантаження показує реальний прогрес, гра не стартує до готовності асетів, звук грає на дії гачка.

## Lab 4 — Node.js: The Other Runtime

**Фокус**: Node vs браузер, CJS vs ESM, `EventEmitter`, streams і backpressure, `http`, npm, `ws`.

**Проєктний крок**:
- npm workspaces: `client/`, `server/` (`shared/` з'явиться в Lab 5).
- Node-сервер на `ws`: кімнати (одна арена = одна кімната), join/leave, чат.
- `RoomManager extends EventEmitter`, емітить `playerJoined`/`playerLeft`.
- Лог матчу — append-only стрім у файл (`fs.createWriteStream`) для join/leave/chat/kill-подій, з урахуванням backpressure (`write()` → `false` → чекати `drain`).
- Клієнт підключається через нативний `WebSocket`; рух ще локальний (без авторитетної симуляції), але чат і join/leave вже живі між вкладками.

**Deliverable**: дві вкладки в одній кімнаті бачать join/leave/чат одна одної в реальному часі; лог матчу росте коректно під навантаженням без витоку пам'яті.

## Lab 5 — Real-Time Networking

**Фокус**: `ArrayBuffer`/`DataView`/типізовані масиви, спільні модулі через workspaces, таймери в Node.

**Проєктний крок** (найважчий і найважливіший):
- Авторитетна симуляція переїжджає на сервер (той самий fixed-timestep код з Lab 1–2, винесений у `shared/`); клієнт шле лише інпут.
- Бінарний протокол: пакети інпуту (напрямок руху, постріл гачка) і снапшоти (позиції/швидкості/стан гачків) через `DataView`/typed arrays замість JSON.
- **Client-side prediction**: клієнт одразу застосовує свій інпут для відгуку; **reconciliation** — переграє непідтверджені інпути при отриманні снапшота сервера.
- Інтерполяція віддалених гравців (рендер трохи "в минулому" між снапшотами), щоб підтягування гачком виглядало плавно попри затримку.
- Ключовий нюанс: постріл гачка клієнт передбачає оптимістично (лінія гачка малюється одразу), але **чи справді зачепив** — вирішує лише сервер; клієнт коригує точку зачеплення при розбіжності.

**Deliverable**: два реальні браузери (можна localhost із симульованою затримкою через dev-проксі) коректно гачать одне одного з правильним підтягуванням; заміряна економія трафіку бінарного протоколу проти JSON.

## Lab 6 — TypeScript

**Фокус**: структурна типізація, discriminated unions, generics, `unknown`, strict mode, рантайм-валідація на межах.

**Проєктний крок**:
- Поступова міграція `shared/`, `server/`, `client/` на TS strict.
- Discriminated union для всіх повідомлень протоколу:
  `ClientMsg = {type:'input',...} | {type:'buyItem',...}`
  `ServerMsg = {type:'snapshot',...} | {type:'hookHit',...} | {type:'goldChanged',...}`
- Валідація на межі WebSocket (напр. zod) — сирим байтам/JSON від клієнта не довіряти ніколи.
- Проста система золота/крамниці з типізованим списком предметів (бутси, +дальність гачка, реген).
- Опційно: легкий фреймворк (Svelte/Vue/React) лише для HUD/крамниці — цикл гри і canvas лишаються vanilla.

**Deliverable**: весь код компілюється під `tsc --strict`; навмисно зіпсований пакет безпечно відхиляється валідацією без падіння сервера.

## Lab 7 — Engines, Memory, and Tests

**Фокус**: внутрішня будова V8 (hidden classes, JIT, GC), профілювання в DevTools, object pooling, Web Workers, Vitest, fast-check, Playwright.

**Проєктний крок**:
- Профілювання циклу симуляції/рендеру під навантаженням (багато гачків/частинок) — знайти GC-паузи від алокацій на кожен кадр.
- Object pooling для гачків і частинок ефектів (іскри влучання, пил промаху).
- Боти: прості скриптовані гравці, що рухаються й стріляють гачком — для навантажувального тесту сервера (N ботів одночасно).
- Vitest unit-тести на геометрію гачка/вектор підтягування; fast-check property-тести (напр. "притягнута позиція завжди лежить на лінії між гравцями"); Playwright e2e-тест — два browser context приєднуються в кімнату й бачать синхронізований стан.

**Deliverable**: задокументоване покращення frame-time p99 після pooling, тести проходять, навантажувальний тест сервера з N ботами.

## Lab 8 — Ship It

**Фокус**: продакшн Node, Docker, CI/CD, WebSocket за проксі, логування, метрики, обмеження зловживань, PWA.

**Проєктний крок**:
- Docker для сервера (+ статична збірка клієнта через Vite build), docker-compose для локального прод-подібного запуску.
- CI/CD (GitHub Actions): lint + typecheck + test на PR, build + deploy на merge у main.
- Реверс-проксі з підтримкою WS upgrade (nginx/Caddy або нативно платформи, напр. Fly.io/Render), TLS.
- Структуроване логування (pino) + базові метрики (гравці, кімнати, пакети/сек) + rate limiting на з'єднання проти спаму гачками/join-флуду.
- Опційно: PWA-маніфест.

**Deliverable**: публічний URL, двоє незнайомців реально дуелять гачками наживо; README оновлено з архітектурною діаграмою, відео-демо та цифрами по трафіку/затримці з Lab 5/7.
